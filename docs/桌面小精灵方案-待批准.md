# 桌面小精灵 + 通知栏直达 实现方案（M-037 设计稿，待老大批准）

> 来源：老大朋友建议（2026-09-06 凌晨）——核心痛点：**每次用都要打开 App 太重了**。
> 需求三件套：①桌面悬浮小精灵（点击展开 沟通/安排 两选项，点选直接语音→发送）
> ②回复走**系统通知栏**（不打开 App 就能看结果；安排直接在通知里读）③点通知跳进 App 看详情。

---

## 一、技术可行性结论（先回答"能不能"）

**能做，且三个部件都有成熟拼装件**（刚完成两轮检索核实）：

| 部件 | 现成方案 | 成熟度 |
|---|---|---|
| 悬浮小精灵 | `floating_window_android`（Flutter 插件，pub.dev 在维护，2025-10 还在更新） | ★★★★ 独立 Flutter UI 悬浮窗+可拖动+边缘吸附+与主 App 双向通信 |
| 通知栏 | `flutter_local_notifications`（Flutter 官方生态最常用通知插件） | ★★★★★ 点击回调带 payload 跳转指定页 |
| 后台存活 | 前台服务（FOREGROUND_SERVICE，悬浮窗插件本身就带通知保活） | ★★★★ 悬浮窗常驻=前台服务常驻 |

**小精灵的形象**：悬浮窗内容是纯 Flutter UI——咱们的时钟+对勾图标直接做成会呼吸的小精灵动画（可用 Lottie 动画或自绘），完全可定制。

## 二、交互流设计

```
桌面任意界面
  └─ 小精灵常驻悬浮（可拖动，贴边收纳，默认屏幕右缘）
       ├─ 点一下 → 弹出两个圆钮：💬沟通 / 📅安排
       │    ├─ 点「沟通」→ 小精灵变成麦克风态（变红呼吸）
       │    │    ├─ 说话 → 再点一下 → 录音结束
       │    │    └─ 转写+发送（后台静默，小精灵变"思考"动画）
       │    └─ 点「安排」→ 同上，mode=arrange
       │
       └─ 结果回来 → 系统通知栏弹出：
            标题=AI 回复摘要（沟通）/「安排好了：3 个时段」（安排）
            正文=回复前 2~3 行或时间块列表
            ├─ 不理它 → 通知栏直接读完，完事
            └─ 点通知 → 拉起 App 跳到对应会话页看全文
```

## 三、架构落点（复用现有管道的关键）

**最大优势：核心逻辑零改动。** 小精灵只是一个新的"入口皮"：

1. **语音链路全复用**：悬浮窗里点沟通→录音→GLM-ASR 转写——跟 App 内麦克风完全同一条 `VoiceInput.transcribe` 管道
2. **发送链路全复用**：转写文本走同一套 `AppState.send(text, arrangeMode:)`——两库组装、AI 调用、验货入账、聊天记录落盘，全部不变。**用户从悬浮窗说的话，账本照记，回 App 看历史一幕都在**
3. **通知层新增**：`send()` 完成后检测「App 在后台」→ 弹系统通知（新依赖 flutter_local_notifications，约 60 行封装）
4. **悬浮窗引擎独立**：floating_window_android 要求独立 Dart 入口（`@pragma("vm:entry-point") overlayMain()`）——小精灵 UI 与主 App 双引擎，插件提供消息通道传数据（录音指令/结果互传）

## 四、实施拆解（两步走，建议分两轮交付）

**第一轮（M-037a）：通知栏直达**——先做收益最大的半边
- 集成 flutter_local_notifications；App 退后台后收到 AI 回复 → 弹通知（安排模式带时间块摘要）
- 点通知跳回对应会话页
- **量级：小**（半轮）。做完后你朋友的核心痛点已解一半：打开 App 说完话就可以切走，结果通知栏看

**第二轮（M-037b）：桌面小精灵**
- 集成 floating_window_android；小精灵 UI（呼吸动画+双选项+麦克风态）
- 悬浮窗录音→传主引擎→复用发送链路；设置页加「桌面小精灵」开关（权限引导：悬浮窗权限 SYSTEM_ALERT_WINDOW）
- **量级：中**（一轮）。风险点：双引擎通信调试 + 国产 ROM 悬浮窗权限兼容（小米/华为要手动开"显示在其他应用上层"）

## 五、需要老大拍板的点

1. **分两轮做同意吗？**（建议：先通知后精灵——通知是地基，精灵是糖衣）
2. **小精灵的形象**：用现有时钟+对勾图标做动画版？还是画一个全新卡通形象（类似小机器人/小猫）？给个方向我出 2~3 版选
3. **Android 专属功能确认**：悬浮窗是安卓特性，Windows 预览版不做（不影响现有任何功能）

## 六、边界与代价（如实交底）

- **权限**：悬浮窗需要「显示在其他应用上层」权限（安装后首次开启时引导，一次授权永久有效）——这是安卓所有悬浮球类 App（如屏幕录制悬浮钮）的标准权限
- **电量**：前台服务常驻有轻微耗电（同类悬浮球 App 水平）；设置页提供开关，不想要随时关
- **token 消耗**：不变——同样的话从悬浮窗说和从 App 说是同一笔账
